**Project:** Alessandro Smedile Personal Site  
**Owner:** Alessandro Smedile  
**Status:** In Progress  
**Last Updated:** 2025-04-15  

---

## Overview

This document outlines the technical and design specifications for the redesign
of the personal website. The goal is to move from the current WordPress
installation to a static site built with Astro, improve performance, simplify
content management, and establish a portfolio that can be shared with potential
clients and collaborators.

The target audience is primarily other professionals — designers, developers,
and product managers who may want to work together or learn from published
content.

---

## Technical Stack

The site will be built using:
- **Framework:** Astro 4.x (static site generation with optional SSR)
- **Styling:** Tailwind CSS v3 (utility-first, no custom CSS unless strictly necessary)
- **Deployment:** Vercel (free tier, auto-deploy from main branch)
- **Content:** Markdown + MDX for blog posts and case studies
- **Analytics:** Plausible (privacy-first, self-hosted on the same Vercel account)

We evaluated Next.js and Hugo but ruled them out. Next.js adds unnecessary
complexity for a content-heavy static site. Hugo's templating language is
opaque and slows down iteration.

## Pages

The site will include the following pages:

### Home
A single-scroll landing page. Hero section with name, one-line role description,
and two CTAs: "View Work" and "Get in Touch". Below the hero: recent projects
(3 cards), a short about paragraph, and a link to the blog.

### Work
A grid of project cards. Each card shows: project name, category tag,
thumbnail, one-line description, and a link to the case study. Filterable
by category (Web, Branding, Product). No pagination — all projects visible
on load (expected: 10–15 projects max).

### Blog
List view. Posts sorted by date descending. Each item shows title, date,
estimated read time, and a short excerpt (first 120 chars of body). No
categories or tags at launch — add later if needed.

### About
Two-column layout on desktop. Left: photo and contact links (email, LinkedIn,
GitHub). Right: bio (~200 words), skills list, timeline of key roles.

### Contact
Simple form: name, email, message, send. Form handled by Formspree (free plan:
50 submissions/month). No captcha at launch — add if spam becomes an issue.

## Design System

### Typography
- **Display:** Fraunces (Google Fonts, variable weight 100–900)
- **Body:** Inter (Google Fonts, 400/500/600)
- **Mono:** JetBrains Mono (code blocks only)
- Base size: 16px. Line height: 1.6 for body, 1.2 for headings.

### Colors
- Background: #0F0F0F (near-black)
- Surface: #1A1A1A
- Primary text: #F5F5F5
- Secondary text: #A3A3A3
- Accent: #F5A623 (amber — used for CTAs, links, and highlights)
- Border: #2E2E2E

### Spacing
8px base unit. Spacing scale: 4, 8, 12, 16, 24, 32, 48, 64, 96px.

## Performance Requirements

- Lighthouse score: ≥ 95 across all four categories (Performance, Accessibility,
  Best Practices, SEO)
- LCP: < 2.5s on mobile (3G)
- CLS: < 0.1
- No JavaScript on pages that don't need it (Home, About, Contact form excluded)

---

## SEO

- Meta title pattern: `{Page Title} — Alessandro Smedile`
- Meta description: manually authored for each page
- Open Graph: og:title, og:description, og:image (per-page or global fallback)
- Canonical URLs required on all pages
- robots.txt: allow all (no staging env to block)
- Sitemap: auto-generated by Astro's sitemap integration

---

## Accessibility

WCAG 2.1 AA compliance required. Specific checks:
- Color contrast ratio ≥ 4.5:1 for body text (background vs. #F5F5F5 is 19.1:1 — passes)
- All images require alt text (decorative images: alt="")
- Keyboard navigation fully functional
- Focus indicators visible on all interactive elements

## Open Questions

1. **Domain:** Keep `alessandrosmedile.com` or switch to shorter `smedile.com`?
   Both are available. Decision deferred — no deadline.

2. **Dark/light mode toggle:** Not in scope for v1 but the palette should be
   designed to support it easily. Use CSS variables from day one.

3. **Blog comments:** Currently planning no comments. Revisit after 3 months
   based on engagement.

4. **Case study format:** Long-form narrative vs. structured brief (problem /
   process / outcome). Decision needed before writing first case study — target
   date 2025-05-01.
